# aqa-sanity-sandbox

A Sanity Studio and Next.js site for building and testing AQA page builder components before they go into aqa.org.uk. It starts with the new hero slider, plus the other homepage sections, all styled with the colours, type and pill buttons from aqa.org.uk.

Owner: Lee Thomas

## What's here

```
aqa-sanity-sandbox/
├── studio/                 Sanity Studio (standalone, Vite)
│   ├── schemaTypes/
│   │   ├── documents/      page, siteSettings
│   │   ├── objects/        link, button, seo
│   │   ├── blocks/         heroSlider, heroSlide, statsBand, quickLinks, cardGrid, ctaBanner, richText
│   │   └── shared/         option lists and the shared "Section" fields

    ├── src/app/            [[...slug]] page route, draft mode routes, AQA tokens in globals.css
    ├── src/components/     page builder, sections, hero-slider, AQA button

    └── sanity.types.ts     Generated by TypeGen
```

## Setup

Needs Node.js 22.12 or newer.

### 1. Create the repo

```bash
# from the unzipped folder
git init && git add -A && git commit -m "Initial sandbox"
gh repo create aqa-sanity-sandbox --private --source=. --push
```

### 2. Install

```bash
npm install
```

### 3. Environment files

```bash
cp studio/.env.example studio/.env
cp web/.env.example web/.env.local
```

- `web/.env.local`: add a **Viewer** token as `SANITY_API_READ_TOKEN`. Create it at sanity.io/manage > AQA Sanity Sandbox > API > Tokens. It is needed for draft mode and the Presentation tool. Published content works without it.
- `studio/.env`: only needed for `npm run seed`. Add an **Editor** token as `SANITY_WRITE_TOKEN`.

Never commit either file. Both are in `.gitignore`.

### 4. Log in, deploy the schema and the Studio

```bash
cd studio
npx sanity login
npx sanity schemas deploy   # lets MCP tools and the Content Lake see the schema
npx sanity deploy           # hosts the Studio at https://aqa-sandbox.sanity.studio
cd ..
```

Then add the hosted Studio and the site URL to CORS:

```bash
cd studio
npx sanity cors add https://aqa-sandbox.sanity.studio --credentials
npx sanity cors add https://<your-vercel-url> --credentials
```

### 5. Run it

```bash
npm run dev
```

- Studio: http://localhost:3333
- Site: http://localhost:3000

In the Studio, open **Presentation** to edit any page with the live site beside the form. Click any text on the page to jump to its field.

### 6. Deploy the site (optional)

On Vercel, import the repo and set **Root Directory** to `web`. Add the three `NEXT_PUBLIC_*` variables and `SANITY_API_READ_TOKEN`. Then set `SANITY_STUDIO_PREVIEW_URL` in `studio/.env` to the Vercel URL and run `npx sanity deploy` again so Presentation previews the hosted site.

## Scripts (from the repo root)

| Command | What it does |
| --- | --- |
| `npm run dev` | Studio and site together |
| `npm run build` | Builds both |
| `npm run seed` | Recreates the example pages (safe to re-run, uses fixed IDs) |
| `npm run typegen` | Extracts the schema and regenerates `web/sanity.types.ts` |
| `npm run deploy:schema` | Deploys the schema to the Content Lake |
| `npm run deploy:studio` | Deploys the hosted Studio |

## AQA styling

Tokens in `web/src/app/globals.css` come from the aqa.org.uk stylesheets:

| Token | Value | Use |
| --- | --- | --- |
| `--aqa-purple` | `#371376` | Primary brand, tabs strip, panels |
| `--aqa-purple-secondary` | `#5f4291` | Secondary panels |
| `--aqa-neutral` | `#2b2438` | Body text, dark overlays |
| `--aqa-red` | `#c8194b` | Primary buttons, badges |
| `--aqa-red-60` | `#de7493` | Button hover, eyebrow rule, progress |
| `--aqa-teal` | `#1fafa3` | Highlighted heading words |
| `--aqa-purple-tint` | `#faf5ff` | Light section background |
| `--aqa-grey` | `#f4f4f4` | Grey section background |

Type is Open Sans, as on the live site. Buttons match the live call to action: 48px high, fully rounded, 2px border, semibold, 16px rising to 18px on large screens. Primary is red with a lighter red hover. Secondary is an outline pill (purple on light backgrounds, white on dark). Text links are red, or white on dark backgrounds.

## How the page builder works

- A **page** has a `sections` array. Editors add components from a grouped insert menu: Heroes, Content, Navigation and Data.
- Every component has a **Section** tab with an anchor ID, background (white, grey, light purple, purple) and spacing. The hero has a width option instead: full width or contained.
- The **first section owns the h1**. Heading levels are not stored in Sanity, so a hero added lower down a page becomes an h2 automatically.
- Hero slides can be **scheduled** with "Show from" and "Show until". The GROQ query filters them, so pages need revalidating on those dates in production.

## Adding a new component

1. Add the schema in `studio/schemaTypes/blocks/`, spread `sectionFields()` into its fields and give it a preview.
2. Register it in `studio/schemaTypes/index.ts` and add its name to `PAGE_BUILDER_BLOCKS` and an insert menu group in `documents/page.ts`.
3. Add a projection for it in `web/src/sanity/queries.ts` if it has links or images.
4. Build the component in `web/src/components/sections/` and add a `case` in `page-builder.tsx`.
5. Run `npm run typegen`, add example content, and deploy the schema.

## Moving the hero into aqa.org.uk

Copy `web/src/components/hero-slider/` and `web/src/components/sections/hero-slider-section.tsx` into the AQA app, and the `heroSlide` and `heroSlider` schema files (plus `link`, `button` and `shared/`) into the AQA Studio. The CSS reads the `--aqa-*` variables when they exist and falls back to the same hex values when they don't.
